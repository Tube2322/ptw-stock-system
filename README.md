# PTW STOCK SYSTEM

ระบบบริหารจัดการสต็อกวัสดุสำหรับโรงพยาบาล (Hospital Material Stock Management) — รับเข้า / เบิกจ่าย / ติดตามสถานะ / วิเคราะห์ต้นทุนวัสดุเทียบตัวชี้วัดการให้บริการ (OPD/IPD)

**Production:** https://ptw-stock-system-shonseys-projects.vercel.app

## สถาปัตยกรรม

โปรเจกต์นี้เป็น **Single-file Static SPA** ไม่มีขั้นตอน build/compile:

- **Frontend:** `index.html` ไฟล์เดียว (HTML+CSS+Vanilla JS) ไม่ใช้ framework, ไม่มี bundler
- **Backend:** [Supabase](https://supabase.com) — Postgres + Auth + Row Level Security (RLS) + RPC (Postgres Functions)
- **Hosting:** Vercel (static hosting, auto-deploy จาก GitHub `main` branch ทุกครั้งที่ push)
- **ไม่มี:** build step, bundler, package manager, unit/integration/E2E test suite, CI pipeline, staging environment

ทุก business logic ที่กระทบข้อมูล (ตัดสต็อก, สร้างเลขที่เอกสาร, ลบข้อมูลย้อนหลัง ฯลฯ) อยู่ใน Postgres Function (`SECURITY DEFINER`) ฝั่ง Supabase ไม่ใช่ฝั่ง client — client เรียกผ่าน `sbClient.rpc(...)` เท่านั้น เพื่อป้องกันไม่ให้ผู้ใช้ปลอมแปลงค่าจากฝั่ง browser

## Roles

ระบบมี 2 สิทธิ์การใช้งาน (บังคับด้วย DB constraint `profiles_role_check` และ `fn_admin_set_role`):

| Role | สิทธิ์ |
|---|---|
| `all` (ผู้ดูแลระบบ) | ใช้งานได้ทุกหน้า ทุกฟังก์ชัน รวมถึงจัดการผู้ใช้/ลบข้อมูลย้อนหลัง/ตั้งค่าบัญชี |
| `viewer` (ผู้ชม) | เห็น**ทุกหน้าและข้อมูลเหมือนแอดมินทุกอย่าง** แต่กดปุ่มที่เขียนข้อมูลไม่ได้เลย (เพิ่ม/บันทึก/อนุมัติ/ปฏิเสธ/จ่ายออก/แก้ไข/ลบ — ปุ่มเหล่านี้ถูกซ่อนทั้งหมด) และ**ไม่เห็นหัวข้อ "ตั้งค่าบัญชี"** เลย (ใช้ได้เฉพาะบัญชีแอดมินเดียวเท่านั้น แม้เรียกตรงผ่านโค้ดก็ยังถูกกันไว้) |

สมัครสมาชิกใหม่ (self-signup) จะได้สิทธิ์ `viewer` เป็นค่าเริ่มต้นเสมอ (ผ่าน DB trigger `handle_new_user`) ต้องรอผู้ดูแลระบบเลื่อนสิทธิ์ให้ในหน้า **ตั้งค่าบัญชี → จัดการผู้ใช้งานและสิทธิ์** — `fn_admin_set_role` ห้ามลดสิทธิ์แอดมินคนสุดท้ายที่เหลืออยู่ในระบบ (รวมถึงตัวเอง) จนกว่าจะมีบัญชีอื่นเป็นแอดมินอยู่ก่อนแล้ว จึงจะลดสิทธิ์ตัวเองได้

## จุดเข้าใช้งานสำหรับผู้เบิก (QR Kiosk Mode)

การเข้าที่ URL พร้อม `#req` (เช่นจากการสแกน QR ในหน้า "ทำใบเบิก") จะเปิด **Kiosk Mode** ปรับ UX ให้เหมาะกับมือถือโดยเฉพาะ:

- ถ้ายังไม่ได้ login → ข้ามหน้า login ไปเลย เข้าฟอร์ม "ทำใบเบิก" ได้ทันทีแบบไม่ต้องมีบัญชี (anonymous) — ผู้กรอกมีหน้าที่กรอกข้อมูลอย่างเดียว ไม่ต้องเก็บ/ยืนยันตัวตนใดๆ
- ซ่อน sidebar และช่องที่ไม่จำเป็น (เลขที่ใบเบิกอัตโนมัติ), dropdown วัสดุขึ้น "— เลือกวัสดุ —" เป็นค่าเริ่มต้นกันกดพลาด, ตารางรายการซ่อนคอลัมน์หน่วย/ราคาบนจอแคบ
- มีแถบล่างค้าง (sticky bar) โชว์จำนวนรายการ+ยอดรวม พร้อมปุ่มส่งคำขอ ไม่ต้องเลื่อนกลับขึ้นบนหลังเพิ่มหลายรายการ
- RLS เปิดสิทธิ์อ่าน (`select`) ให้ผู้ใช้ anon เฉพาะตาราง `departments` และ `products` เท่านั้น (ตารางอื่นยังคงต้อง login)

## พฤติกรรมจริงของ "ใบเบิก" — ต้องผ่านอนุมัติก่อนตัดสต็อก

ใบเบิกทุกใบ (ทั้งจากผู้ใช้ที่ login และจาก QR kiosk แบบไม่ login) ไหลผ่านขั้นตอนนี้:

```
ทำใบเบิก (ส่งคำขอ)
  → "รอตรวจสอบ" (ยังไม่ตัดสต็อก)
  → หน้า "ตรวจสอบใบเบิก": คลังกด อนุมัติ / ปฏิเสธ
       - ปฏิเสธ → จบที่ "ปฏิเสธ" ไม่ตัดสต็อก
       - อนุมัติ → "อนุมัติแล้ว" (ยังไม่ตัดสต็อก)
  → หน้า "จ่ายออก": คลังกรอกจำนวนจ่ายจริง (น้อยกว่าที่ขอได้) → ยืนยัน
  → ตรงนี้เท่านั้นที่ตัดสต็อกจริง → "จ่ายแล้ว"
```

`fn_save_requisition` สร้างใบเบิกสถานะ "รอตรวจสอบ" เท่านั้น ไม่แตะสต็อก — การตัดสต็อกทำโดย `fn_issue_requisition` ที่ขั้นตอนจ่ายออกเพียงจุดเดียว ผู้ดูแลระบบยังแก้ไขจำนวน "จ่ายจริง" ของใบเบิกที่จ่ายแล้วย้อนหลังได้ผ่านปุ่ม "✎ แก้ไข" ในหน้ารายละเอียดใบเบิก (ระบบคำนวณส่วนต่างปรับสต็อกให้อัตโนมัติ พร้อมให้ยืนยันก่อนบันทึกจริง)

## หมวดหมู่สินค้า (ผ้า / สิ้นเปลือง)

สินค้าแต่ละรายการตั้งค่า "หมวดหมู่" ได้ (`สิ้นเปลือง` ค่าเริ่มต้น / `ผ้า`) ใช้แยกต้นทุนในการ์ด Dashboard "ต้นทุนวัสดุแยกหมวดหมู่" ที่ดูได้ทั้งแบบรายวัน (14 วันล่าสุด) และรายสัปดาห์ (8 สัปดาห์ล่าสุด)

## บันทึกการทำงานของ Flow (Run History)

หน้านี้บันทึกทุกการทำงานอัตโนมัติในระบบแบบละเอียด — **ใครทำ, ทำอะไร, เมื่อไหร่** (คอลัมน์ผู้ทำรายการมาจาก `flow_log.by_user` ที่ถูกส่งมาจากทุก RPC ที่เขียนข้อมูล เหตุการณ์ที่ระบบทำเอง เช่น แจ้งเตือนสต็อกต่ำ จะขึ้น "ระบบอัตโนมัติ") มี dropdown เลือกดูรายเดือนและช่องค้นหา — ข้อมูลสะสมยาวไม่มีลบเอง (ไม่ถูกกระทบจาก "ลบข้อมูลย้อนหลังรายเดือน" ด้านล่าง เพราะนั่นลบแค่ใบเบิก/ใบรับ/ledger เท่านั้น)

## ลบข้อมูลย้อนหลังรายเดือน

ผู้ดูแลระบบลบข้อมูล "ใบเบิก / ใบรับ / ประวัติเคลื่อนไหวสต็อก (ledger)" ของเดือนใดเดือนหนึ่งทิ้งถาวรได้ที่ **ตั้งค่าบัญชี → ลบข้อมูลย้อนหลังรายเดือน** — บังคับให้ export CSV ก่อนเสมอ (ปุ่มลบถูกล็อกจนกว่าจะโหลดข้อมูลแล้ว) และต้องพิมพ์รหัสผ่านบัญชีจริงยืนยันตัวตน (ตรวจสอบฝั่ง server) ก่อนลบ ข้อมูลที่**ไม่ถูกลบ**: ยอดสต็อกปัจจุบัน, Monthly KPI, สินค้า/หน่วยงาน, บัญชีผู้ใช้ทุกคน, บันทึก Flow (Run History)

หมายเหตุ: ปุ่ม "รีเซ็ตข้อมูลระบบทั้งหมด" (`fn_admin_reset_data`) ถูกเอาออกจาก UI แล้วตามคำขอ — ฟังก์ชันยังอยู่ในฐานข้อมูล เรียกผ่านแชทกับผู้ดูแลระบบเมื่อจำเป็นเท่านั้น

## Database

Supabase project: `ekvjwdistihmkcuquayl` — ตารางหลัก: `products` (มีคอลัมน์ `category`), `departments`, `requisitions`, `requisition_items`, `receives`, `stock_transactions` (ledger), `monthly_kpi`, `profiles`, `flow_log` (มีคอลัมน์ `by_user`)

Postgres Functions (ทั้งหมด `SECURITY DEFINER`, bypass RLS ภายใน แต่มีการเช็คสิทธิ์เองในตัวฟังก์ชัน):

- `fn_save_requisition` — บันทึกใบเบิกสถานะ "รอตรวจสอบ" (validate: จำนวน>0, มีสินค้าพอ) ไม่ตัดสต็อก
- `fn_save_receive` — บันทึกใบรับเข้า + เพิ่มสต็อกทันที (validate: จำนวน>0, ราคาไม่ติดลบ)
- `fn_approve_requisition` / `fn_reject_requisition` / `fn_issue_requisition` — อนุมัติ/ปฏิเสธ/จ่ายออก — **`fn_issue_requisition` เป็นจุดเดียวที่ตัดสต็อกจริงของใบเบิก**
- `fn_admin_edit_requisition_item` — แก้ไขจำนวนจ่ายจริงย้อนหลัง (admin only)
- `fn_admin_set_role` — ปรับสิทธิ์ผู้ใช้ (admin only, จำกัดค่าเป็น `all`/`viewer`, ห้ามลดสิทธิ์ตัวเองหรือใครก็ตามถ้าจะทำให้ระบบไม่เหลือแอดมินเลย — ลดสิทธิ์ตัวเองได้ก็ต่อเมื่อมีแอดมินคนอื่นอยู่แล้ว)
- `fn_admin_reset_data` / `fn_admin_purge_month` — ล้างข้อมูลทั้งหมด (ไม่มีปุ่มใน UI แล้ว) / ลบข้อมูลย้อนหลังรายเดือน (admin only + ยืนยันรหัสผ่านสำหรับ purge)
- `fn_post_tx` / `fn_next_no` — internal helpers (ลงบัญชี ledger, ออกเลขที่เอกสาร)
- `fn_block_product_delete_with_history` — BEFORE DELETE trigger บนตาราง `products` บล็อกการลบสินค้าที่มีประวัติใน `requisition_items`/`stock_transactions`/`receives` ระดับฐานข้อมูล (ไม่ใช่แค่เช็คฝั่ง client)

RLS เปิดใช้งานทุกตาราง — สิทธิ์เขียนทั้งหมดจำกัดเฉพาะผู้ใช้ที่ login และไม่ใช่ `viewer` (`not is_viewer()`) ยกเว้น `stock_transactions` ที่ปิดการ insert ตรงจาก client ทั้งหมด (ต้องผ่าน `fn_post_tx` เท่านั้น) และ `departments`/`products` ที่เปิด `select` ให้ผู้ใช้ `anon` เพื่อรองรับฟอร์ม kiosk

## Session

Login คงอยู่ข้ามการเปิดเว็บใหม่บนเบราว์เซอร์/เครื่องเดิมโดยอัตโนมัติ (Supabase persist session ใน `localStorage` + auto-refresh token) จนกว่าจะกด "ออกจากระบบ" เอง — ระบบเช็ค session ทุก 5 นาที ถ้าหมดอายุจริงจะเด้ง alert กลับหน้า login อัตโนมัติ (แยกจากกรณี logout ปกติด้วย flag `loggingOut` ไม่ให้ขึ้น alert ซ้อน)

## Deployment

Push ไปที่ branch `main` → Vercel deploy อัตโนมัติ ไม่มี environment variables (Supabase URL + anon key ฝังในไฟล์โดยตั้งใจ เนื่องจากเป็น client-side public key ที่ถูกป้องกันด้วย RLS อยู่แล้ว)
